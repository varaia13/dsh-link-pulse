# Changelog

## [0.1.12] - 2026-09-28
### Изменено
- Отображение имени модели изменено на полный исходный model ID (например `gpt-6-astra`), сокращения GPT, Gemini, Claude, DeepSeek и т.д. больше не применяются.
### Исправлено
- Исправлено постоянное отображение CPA · Gemini 3.7 при переключении модели: вместо чтения отсутствующего `sessions.list.current` для получения ID главногосессии используется DSH `uiSession.current`.
- Добавлены декларации внедрения зависимостей клиента `sessions`, `modelDirectories`, `uiSession`.
- При ещё не поступившей конфигурации backend-дефолта больше не хардкодится CPA/Gemini 3.7, вместо этого ожидается фактическая конфигурация модели по умолчанию.

## [0.1.8] - 2026-08-30
### Исправлено
- **Официальный провайдер DeepSeek V4 показывался как CPA**: runtime provider id встроенного официального маршрута DSH — `deepseek-official` (константа `PROVIDER` в `dsh-llm-deepseek`), а запасной официальный узел плагина регистрировал id `deepseek`, из-за чего поиск клиента по provider текущей сессии не находил его и ошибочно откатывался к первому элементу списка (CPA). id запасного узела исправлен на `deepseek-official`, маппинг `KNOWN_PROVIDER_DEFAULTS` зарегистрирован синхронно.
- **Нераспознанные Provider путались**: при неудачном поиске в providerMap клиент больше не показывает имя и задержку первого провайдера списка от его имени, вместо этого показывается реальный id провайдера (в верхнем регистре), задержка показана.

## [0.1.7] - 2026-08-29
### Исправлено и отрефакторено
- **Рефактор подписки на авторитетное состояние**: полностью убраны поллирование клиентским таймером DOM-скрапинг, подключены нативные сервисы DSH `sessions` и `modelDirectories`, переключение модели мгновенно при выборе (0 мс), без необходимости отправлять сообщение для триггера.
- **Изоляция шлюзов Provider и одноимённых моделей**: провайдеры изолированы по отдельности (официальный `deepseek` — `https://api.deepseek.com`, `opencode-go` — `https://opencode.ai`), устранены конфликт пространства имён и ошибочная атрибуция серии DeepSeek V4 между официальным и OpenCode GO.

## [0.1.6] - 2026-08-25
### Документация
- В README добавлены описания принципа Keep-Alive чистого 1-RTT-замера и сравнительная таблица холодного рукопожатия против горячего долгого соединения.

## [0.1.5] - 2026-08-25
### Изменено
- Оптимизирована вёрстка постоянного элемента боковой панели: значение задержки (например `126ms`) переведено в единый компактный сегментный формат спецификации OpenCode / CPA (`● CPA · Gemini 3.7 · 126ms`), убрано насильное растягивание двумя крайами через `space-between`, достигнута 100% визуальная пиксельная выровненность.

## [0.1.4] - 2026-08-25
### Изменено
- Алгоритм зонда upgraded до Keep-Alive чистого RTT-замера: после готовности TLS-туннеля замеряется чистое время往返 HTTP-данных (1-RTT), реально отражающее задержку сетевого пульса в сценариях диалога на долгом соединении (прямое CPA-соединение в Германии снизилось с ~450ms до фактического физического往返 ~126ms).

## [0.1.3] - 2026-08-25
### Исправлено
- Исправлено расхождениевнутренних и внешних отображений задержки: введены глобальный синглтон состояния и 25-секундный backend-кэш зонда (поддерживает `?refresh=1` принудительное обновление), обеспечивающие 100% синхронность и общий источник данных задержки для кнопки сайдбара, hover-карточки и полноэкранного дашборда.

## [0.1.2] - 2026-08-25
### Изменено
- Из списка сравнения Provider-каналов убрано дублирование текущего основного канала: текущий основной уже выделен сверху, список ниже показывает сравнение замера «доступных других Providers» (hover-слой и полноэкранный дашборд обновляются синхронно).

## [0.1.1] - 2026-08-25
### Исправлено
- Активно вычищены UI-метки-остатки «default / reasoning level / model» из текста селектора модели, чтобы длинные model ID (например `opencode minimax-m3`) распознавались корректно одним токеном.
